# 缓存设计（Redis 缓存层）

> 目标：给读多写少的热点只读路径加缓存，缓解 DB 压力、降低 P95 延迟；用一套统一方案覆盖缓存穿透/击穿/雪崩与缓存一致性。

## 1. 整体架构

缓存基础设施全部下沉在 `ai-saas-common`，业务模块开箱即用：

- **`RedisConfig`**：根据 `spring.data.redis.*` 构建 `RedissonClient`（单点/哨兵/集群可切）、`RedisTemplate`（JSON 序列化），并新增 **`RedisCacheManager`** —— 业务方用标准 `@Cacheable` / `@CacheEvict` 即可，无需每个服务各自配置。
- **`RedisUtils`**：封装分布式锁（`getLock`/`tryLock`）、令牌桶限流（`RRateLimiter`）、布隆过滤器（`getBloomFilter`）等，用于更高级的防护。
- **`docker-compose`** 已带 `redis:7-alpine`（无密码，6379）。

各缓存命名空间 TTL（在 `RedisCacheManager` 中配置）：

| 命名空间 | 内容 | TTL | 说明 |
|---|---|---|---|
| `user` | 用户信息（`UserAccount`） | 30 min | 变更少，命中率极高 |
| `quota` | 配额记录（`QuotaRecord`） | 3 s | 强一致读路径（Feign 同步校验），短 TTL + 写时失效 |
| `conversation` | 会话列表分页 | 30 s | 中频写，短 TTL 自愈 |

## 2. 三大经典问题的解法

- **缓存穿透**（查不存在的 key，打到 DB）：用户缓存 `getById` 用**布隆过滤器预筛**——`UserBloomFilter` 启动时从 DB 全量载入 `userId` 构建 `RBloomFilter`（误判率 1%，预留 100w），回源 DB 前先 `mightContain`：判定"一定不存在"直接返回 null 拦截穿透（且不进缓存）；注册新用户时增量 `add`；过滤器不可用时 fail-open 放行（走 DB），不挡正常请求。其余命名空间（quota/conversation）用 `@Cacheable(unless = "#result == null")` **不缓存空值**。
- **缓存击穿**（热点 key 失效瞬间，大量并发回源）：用户缓存 `getById` 用 `@Cacheable(sync = true)` 由 Spring 对**同一个 key 加锁**，保证单线程回源；⚠️ 注意 `sync=true` 与 `unless` 互斥（Spring 限制：unless 在返回后求值，无法与调用前 singleflight 共存），故用户缓存的空值防护改由布隆过滤器承担，而非 `unless`。需要跨 JVM 的 singleflight 时，可用 `RedisUtils.getLock` 手动实现。
- **缓存雪崩**（大量 key 同时失效）：各命名空间设置**不同 TTL**，避免集体失效；若要求更严，可在 `RedisCacheManager` 给 TTL 加随机 jitter（文档方案，可按需补充）。

## 3. 一致性策略（Cache-Aside）

- **读**：走 `@Cacheable`，命中直接返回，未命中回源 DB 并写入。
- **写**：走 `@CacheEvict` 主动失效（而非更新缓存，避免并发写导致的脏数据）。
- 取舍：
  - `user`：在**所有写操作**（`updateProfile` / `uploadAvatar` / `changePassword` / `changePhone` / `changeEmail` / `unbindThirdPartyAccount` / `updateUserStatus` / `deleteUser`）时按 `userId` 失效，覆盖"改资料后读到旧数据"的盲区。
  - `quota`：TTL 仅 3s，且 `deductQuota` / `updateQuotaConfig` 时主动失效，平衡了"强一致校验"与"减少 DB/Feign 往返"。
  - `conversation`：会话列表分页 key 含分页参数，写操作（增删改/置顶/归档/清空消息）用 `allEntries = true` 整命名空间失效，简单可靠（写频率远低于读）。

## 4. 接入的三个热点只读路径

| 路径 | 方法 | 频率 | 失效点 |
|---|---|---|---|
| 用户信息 | `UserServiceImpl.getById`（auth 每次鉴权都打，已路由 `AuthServiceImpl` 走此；回源前经布隆预筛） | 极高 | 全部写操作变更 |
| 配额记录 | `QuotaServiceImpl.getQuotaRecord`（chat→billing 的 Feign 同步配额校验，每次对话前必打） | 高 | 扣减/配置变更 |
| 会话列表 | `ChatConversationServiceImpl.listConversations` / `listArchivedConversations`（已配联合索引） | 中高 | 会话增删改/置顶/归档/清空 |

## 5. 顺带修复的配置坑

各服务原 yml 写的是 `spring.redis.*`，但 `spring-boot-starter-data-redis` 只认 `spring.data.redis.*`，导致除 chat 外都回退到 `localhost:6379` 且无法切换环境。已统一改为 `spring.data.redis.*`（user / billing / task / rag）。
